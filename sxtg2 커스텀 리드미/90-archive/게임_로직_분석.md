## 개요

이 문서는 **Sixtar Gate STARTRAIL** 게임의 원본 로직을 분석한 것입니다. 게임 코드가 난독화되어 있어 직접적인 소스 코드를 확인할 수 없지만, 모드가 후킹하는 메서드와 데이터 구조를 역으로 추론하여 게임의 동작 방식을 추정했습니다.

게임은 Unity 엔진으로 제작되었으며, 리듬 게임의 핵심 기능인 BMS 파일 파싱, 노트 데이터 관리, 게임 플레이 상태 관리 등을 구현하고 있습니다.

## 게임의 데이터 구조

### 1. SXGTData 클래스

게임의 차트 데이터를 담는 핵심 클래스입니다. 모드 코드에서 후킹하는 부분을 보면 다음과 같은 구조를 가집니다:

#### 주요 필드/프로퍼티:
- **laneData**: `Dictionary<int, List<NoteData>>` - 각 레인(0-9)별로 노트 데이터를 저장하는 딕셔너리
- **maxScore**: `float` - 최대 스코어 제한값 (기본값: 1,000,000)
- **cruiseFinishTime**: `float` - 게임 종료 시간 (초 단위)
- **unfinished**: `Dictionary<...>` - 미완성 홀드 노트를 추적하는 딕셔너리

#### 생성 시점:
- `SXGTReader.ReadBMSFile()` 또는 `SXGTReader.ParseString()` 메서드가 BMS 파일을 파싱한 후 생성됩니다.
- 생성자 호출 시점에 `laneData`가 초기화되고 노트 데이터가 채워집니다.

### 2. NoteData 클래스

개별 노트의 데이터를 표현하는 클래스입니다. 모드 코드에서 추정한 구조:

#### 주요 필드:
- **timing**: `float` - 노트의 타이밍 (초 단위, 게임 시작 시점 기준)
- **nType**: `NoteType` enum - 노트 타입 (SHORT, HOLD 등)
- **nColor**: `NoteColor` enum - 노트 색상 (BLUE, RED, OPEN 등)
- **targetLane**: `int` - 노트가 배치될 레인 (0-9)
- **duration**: `float` - 홀드 노트의 지속 시간 (초 단위)
- **tickTime**: `float[]` - 홀드 노트의 틱 배열 (각 틱의 시간을 저장)

#### 노트 타입:
- **ShortNote**: 짧은 노트 (BMS 값 01)
- **HoldNote**: 홀드 노트 (BMS 값 02, 03)
- **OpenNote**: 오픈 노트 (BMS 값 04, 05)

### 3. 레인 매핑

게임은 10개의 레인(0-9)을 사용합니다:

- **레인 0-3**: 일반 노트 레인 (BMS 채널 16, 15, 14, 13)
- **레인 4-5**: 빨간색 노트 레인 (BMS 채널 12, 11) - `nColor: RED`
- **레인 6-8**: 일반 노트 레인 (BMS 채널 18, 17, 16)
- **레인 9**: 오픈 노트 레인 (BMS 채널 04, 05) - `nColor: OPEN`

### 4. Pattern 및 StartrailPattern 클래스

게임의 패턴 데이터를 담는 클래스입니다:

- **Pattern**: 기본 패턴 클래스
  - **MasterBPM**: `float` - 마스터 BPM 값
- **StartrailPattern**: 스타트레일 전용 패턴 클래스
  - **Notes**: `List<NoteData>` - 노트 리스트
  - **NoteCount**: `int` - 노트 개수

## BMS 파일 로드 및 파싱 과정

### 1. 트랙 선택

사용자가 트랙을 선택하면:

1. **SelectableTrackObject** 인스턴스가 생성됩니다.
2. **TrackData**가 로드되어 트랙의 메타데이터(ID, DisplayName 등)를 가져옵니다. (모드 주입 기준: 제목 문자열은 인스턴스 **필드** `DisplayName`에 `SetValue` — `IMPLEMENTATION.md` 참고.)
3. 트랙의 BMS 파일 경로가 결정됩니다.

### 2. BMS 파일 로드

게임은 다음 메서드를 통해 BMS 데이터를 로드합니다:

#### ManagerPlay.set_bms
- `SXGTData` 인스턴스를 받아서 `ManagerPlay`의 내부 필드에 저장합니다.
- 이 시점에서 게임은 차트 데이터를 준비합니다.

#### ManagerPlay.FetchBMSToModules
- 트랙 디렉토리에서 BMS 파일을 찾아 로드합니다.
- 내부적으로 `SXGTReader.ReadBMSFile()` 또는 `ManagerPlay.GetPatternFromDir()`를 호출합니다.

#### ManagerPlay.GetPatternFromDir
- 디렉토리 경로를 받아서 BMS 파일을 찾고 파싱합니다.
- `SXGTData` 인스턴스를 반환합니다.

### 3. BMS 파일 파싱

게임은 `SXGTReader` 클래스를 사용하여 BMS 파일을 파싱합니다:

#### SXGTReader.ReadBMSFile
- 파일 경로를 받아서 BMS 파일을 읽습니다.
- 내부적으로 `LoadTextAssetFromBundle()`을 호출하여 `TextAsset`을 로드합니다.
- `ParseString()` 또는 `ParseStream()`을 호출하여 BMS 텍스트를 파싱합니다.
- 최종적으로 `SXGTData` 인스턴스를 생성하고 반환합니다.

#### SXGTReader.ParseString
- BMS 텍스트를 `string[]` 배열로 받아서 파싱합니다.
- 각 라인을 순회하면서:
  - 헤더 라인 (`#BPM`, `#BPMXX` 등)을 파싱하여 BPM 정보를 추출합니다.
  - 노트 데이터 라인 (`#XXXXXX:YY` 형태)을 파싱하여 노트를 생성합니다.
- 첫 번째 파라미터로 `SXGTData` 인스턴스를 받아서 (ref 파라미터) 노트를 추가합니다.

#### SXGTReader.ParseBeatString
- 개별 BMS 라인 (`#06656:0202` 형태)을 파싱합니다.
- BMS 포맷: `#MMMCC:데이터`
  - `MMM`: Measure (마디 번호, 3자리)
  - `CC`: Channel (채널 번호, 2자리)
  - `데이터`: 16진수 문자열 (2자리씩 쌍으로 읽음)
- 데이터 문자열을 2자리씩 읽어서:
  - 첫 번째 문자: 레인 번호 (0-9는 0-9, A-Z는 10-35)
  - 두 번째 문자: 노트 타입 또는 데이터 값
- 파싱된 노트를 `SXGTData.laneData`에 추가합니다.

### 4. BMS → 노트 변환 과정

게임은 BMS 파일의 노트 데이터를 게임 내부 형식으로 변환합니다:

1. **BMS 채널 → 게임 레인 매핑**:
   - BMS 채널 16, 15, 14, 13 → 게임 레인 0, 1, 2, 3
   - BMS 채널 12, 11 → 게임 레인 4, 5 (RED)
   - BMS 채널 18, 17, 16 → 게임 레인 6, 7, 8
   - BMS 채널 04, 05 → 게임 레인 9 (OPEN)

2. **BMS 노트 값 → 게임 노트 타입**:
   - `01` → `SHORT` (ShortNote)
   - `02` → `HOLD` (HoldNote 시작)
   - `03` → `HOLD_END` (HoldNote 종료, 파싱 후 제거됨)
   - `04` → `HOLD` (OpenNote 시작)
   - `05` → `HOLD_END` (OpenNote 종료, 파싱 후 제거됨)

3. **타이밍 계산**:
   - BMS의 Measure(마디)와 Position(위치)를 실제 시간(초)으로 변환합니다.
   - 현재 BPM을 사용하여 계산합니다.
   - **제한사항**: 게임은 BPM 변경 채널(03, 04, 08)을 완전히 지원하지 않을 수 있으며, 초기 `#BPM` 헤더만 사용할 수 있습니다.

4. **홀드 노트 길이 계산**:
   - `02` (Long) 노트와 `03` (HoldEnd) 노트를 매칭하여 홀드 길이를 계산합니다.
   - `04` (Open) 노트와 `05` (Close) 노트도 동일하게 처리합니다.
   - `HoldEnd`와 `Close` 노트는 파싱 결과에서 제거되고, `Long`과 `Open` 노트의 `duration` 필드에 길이가 저장됩니다.

### 5. SXGTData 생성

BMS 파싱이 완료되면:

1. `SXGTData` 생성자가 호출됩니다.
2. 생성자 내부에서:
   - `laneData` 딕셔너리가 초기화됩니다.
   - 각 레인별로 `List<NoteData>`가 생성됩니다.
   - 파싱된 노트들이 `laneData`에 추가됩니다.
   - `maxScore`가 계산되거나 설정됩니다 (기본값: 1,000,000).
   - `cruiseFinishTime`이 마지막 노트의 타이밍을 기반으로 계산됩니다.

## 노트 데이터 생성 및 변환

### 1. NoteData 객체 생성

게임은 파싱된 BMS 노트 데이터를 `NoteData` 객체로 변환합니다:

1. **생성자 호출**:
   - `NoteData` 생성자는 여러 오버로드가 있을 수 있습니다:
     - `(float timing, int targetLane)` - 기본 생성자
     - `(float timing, NoteType nType, NoteColor nColor, int targetLane)` - 전체 파라미터
     - `(float timing, NoteType nType, NoteColor nColor, int targetLane, float duration)` - 홀드 노트용

2. **필드 설정**:
   - `timing`: BMS의 Measure와 Position을 초 단위로 변환한 값
   - `nType`: BMS 노트 값에 따라 결정 (SHORT 또는 HOLD)
   - `nColor`: 레인에 따라 결정 (레인 4, 5는 RED, 레인 9는 OPEN, 나머지는 BLUE)
   - `targetLane`: BMS 채널을 게임 레인으로 매핑한 값
   - `duration`: 홀드 노트의 경우 시작과 끝 노트 사이의 시간 차이
   - `tickTime`: 홀드 노트의 경우 틱 배열 생성 (일정 간격으로 나눈 시간 배열)

3. **laneData에 추가**:
   - 생성된 `NoteData` 객체가 해당 레인의 `List<NoteData>`에 추가됩니다.
   - 리스트는 타이밍 순으로 정렬되어 있을 수 있습니다.

### 2. 홀드 노트 처리

홀드 노트의 경우:

1. **시작 노트와 끝 노트 매칭**:
   - 같은 레인에서 `02` (Long) 노트와 다음 `03` (HoldEnd) 노트를 찾습니다.
   - 두 노트 사이의 시간 차이를 `duration`으로 설정합니다.

2. **tickTime 배열 생성**:
   - 홀드 노트의 `duration`을 일정 간격(기준값)으로 나눕니다.
   - 각 틱의 시간을 `float[]` 배열로 저장합니다.
   - 이 배열은 게임이 홀드 노트를 렌더링할 때 사용됩니다.

3. **끝 노트 제거**:
   - `HoldEnd` (03)와 `Close` (05) 노트는 파싱 결과에서 제거됩니다.
   - 게임은 시작 노트만 `laneData`에 저장하고, `duration`과 `tickTime`으로 홀드 길이를 표현합니다.

## 게임 플레이 흐름

### 1. 씬 로드

게임이 플레이 씬을 로드하면:

1. Unity의 `SceneManager`가 플레이 씬을 로드합니다.
2. 씬 이름에 "Play", "Game", "Rhythm" 등이 포함되어 있습니다.
3. 씬이 완전히 로드되면 게임 오브젝트들이 초기화됩니다.

### 2. ManagerPlay 초기화

`ManagerPlay`는 게임 플레이의 핵심 매니저입니다:

1. **싱글톤 인스턴스**:
   - `ManagerPlay.Instance` 또는 유사한 방식으로 싱글톤 인스턴스가 생성됩니다.

2. **BMS 데이터 설정**:
   - `set_bms(SXGTData)` 메서드가 호출되어 차트 데이터가 설정됩니다.
   - 또는 `FetchBMSToModules()`가 호출되어 BMS 파일을 로드하고 파싱합니다.

3. **위젯 초기화**:
   - `InitializeWidgets(string[] widgetIDs)` 메서드가 호출되어 UI 위젯들이 초기화됩니다.
   - 각 위젯의 `OnInitializeByManager()` 메서드가 호출될 수 있습니다.

### 3. 노트 생성

게임은 `NoteGenerator` 클래스를 사용하여 시각적 노트 오브젝트를 생성합니다:

#### NoteGenerator.Generate
- `SXGTData`의 `laneData`를 순회하면서 각 노트에 대해:
  - `RG_NoteObject` 컴포넌트를 가진 `GameObject`를 생성합니다.
  - 노트의 타이밍, 레인, 타입, 색상 등을 설정합니다.
  - 노트를 해당 레인의 "Note Group" `Transform`의 자식으로 배치합니다.

#### Note Group 구조
- 게임 씬에는 각 레인별로 "Note Group" `GameObject`가 있습니다.
- `ManagerPlay.gear.laneGroup.laneDic[레인번호].NoteGroup`으로 접근할 수 있습니다.
- 생성된 노트 오브젝트들이 이 그룹의 자식으로 배치됩니다.

### 4. 게임 플레이 루프

게임은 Unity의 `Update()` 메서드를 통해 매 프레임 업데이트됩니다:

1. **시간 업데이트**:
   - 게임 시간이 경과합니다.
   - BGM이 재생됩니다.

2. **노트 렌더링**:
   - 현재 시간에 맞춰 화면에 표시될 노트들이 렌더링됩니다.
   - 노트는 타이밍에 따라 화면에서 이동합니다.

3. **입력 처리**:
   - 사용자의 키보드/터치 입력을 처리합니다.
   - 노트와의 충돌을 감지하여 판정을 내립니다.

4. **게임 종료 체크**:
   - `ManagerPlay.CheckGameFinished(float currentTime)` 메서드가 주기적으로 호출됩니다.
   - 현재 시간이 `bgmLength`를 초과하면 게임이 종료됩니다.

### 5. 게임 종료

게임이 종료되면:

1. **CheckGameFinished**:
   - 현재 시간이 `bgmLength`를 초과하는지 확인합니다.
   - 모든 노트가 처리되었는지 확인합니다.

2. **FinishPlayScene**:
   - 결과 화면으로 이동합니다.
   - 최종 스코어, 판정 등을 표시합니다.

## 노트 렌더링 및 생성

### 1. RG_NoteObject

게임의 시각적 노트 오브젝트는 `RG_NoteObject` 컴포넌트를 가진 `GameObject`입니다:

- **Timing**: 노트의 타이밍 (초 단위)
- **Lane**: 노트가 배치된 레인
- **NoteType**: 노트 타입 (SHORT, HOLD 등)
- **NoteColor**: 노트 색상 (BLUE, RED, OPEN 등)

### 2. NoteGenerator

`NoteGenerator`는 `SXGTData`의 노트 데이터를 시각적 오브젝트로 변환합니다:

1. **laneData 순회**:
   - 각 레인의 노트 리스트를 순회합니다.

2. **노트 오브젝트 생성**:
   - 각 `NoteData`에 대해 `RG_NoteObject`를 생성합니다.
   - 노트의 타이밍, 레인, 타입, 색상 등을 설정합니다.

3. **부모 설정**:
   - 노트를 해당 레인의 "Note Group"의 자식으로 배치합니다.

### 3. 노트 그룹 구조

게임 씬의 노트 그룹 구조:

```
ManagerPlay
  └── gear
      └── laneGroup
          └── laneDic[레인번호]
              └── NoteGroup (Transform)
                  ├── 노트 오브젝트 1
                  ├── 노트 오브젝트 2
                  └── ...
```

## 게임 상태 관리

### 1. ManagerPlay

`ManagerPlay`는 게임 플레이의 전반적인 상태를 관리합니다:

#### 주요 필드/프로퍼티:
- **bms**: `SXGTData` - 현재 플레이 중인 차트 데이터
- **bgmLength**: `float` - BGM 길이 (초 단위), 게임 종료 시간 결정에 사용
- **targetBestScore**: `float` - 목표 최고 스코어

#### 주요 메서드:
- **set_bms(SXGTData)**: 차트 데이터를 설정합니다.
- **get_bms()**: 현재 차트 데이터를 반환합니다.
- **FetchBMSToModules()**: BMS 파일을 로드하고 파싱합니다.
- **GetPatternFromDir(string bmsDir, ...)**: 디렉토리에서 패턴을 로드합니다.
- **CheckGameFinished(float currentTime)**: 게임 종료 조건을 확인합니다.
- **FinishPlayScene()**: 결과 화면으로 이동합니다.
- **InitializeWidgets(string[] widgetIDs)**: UI 위젯들을 초기화합니다.

### 2. 게임 종료 조건

게임은 다음 조건에서 종료됩니다:

1. **시간 기반**:
   - 현재 시간이 `bgmLength`를 초과하면 종료됩니다.
   - `CheckGameFinished()` 메서드가 이를 확인합니다.

2. **노트 기반**:
   - 모든 노트가 처리되었는지 확인할 수 있습니다.
   - 하지만 게임은 주로 시간 기반으로 종료됩니다.

### 3. BGM 길이 관리

게임은 `bgmLength`를 사용하여 게임 종료 시간을 결정합니다:

- `bgmLength`는 `SXGTData.cruiseFinishTime` 또는 마지막 노트의 타이밍을 기반으로 설정됩니다.
- `get_bgmLength()` 프로퍼티 getter가 호출될 때마다 현재 값을 반환합니다.
- 게임이 `bgmLength`를 초과하면 자동으로 종료됩니다.

## 스코어 시스템

### 1. 스코어 계산

게임은 노트 판정에 따라 스코어를 계산합니다:

- 각 노트마다 일정한 점수가 부여됩니다.
- `SXGTData.maxScore`가 최대 스코어 제한값입니다 (기본값: 1,000,000).

### 2. 스코어 제한

게임은 다음과 같은 스코어 제한을 가지고 있습니다:

- **SXGTData.maxScore**: 차트 데이터의 최대 스코어 (기본값: 1,000,000)
- **ManagerPlay.targetBestScore**: 목표 최고 스코어
- **SXGTReader의 스코어 관련 필드**: 파싱 시 계산되는 스코어 값들

### 3. 스코어 사운드

게임은 특정 스코어 달성 시 사운드를 재생합니다:

- "Clear_Normal": 일반 클리어 사운드
- "Clear_FullCombo": 풀콤보 달성 사운드
- "Clear_FullCombo_JP": 풀콤보 달성 사운드 (일본어)
- `SoundObject.Play()` 또는 `SoundObject.PlayAndDestroy()` 메서드가 호출됩니다.

**모드의 사운드 교체:**
- `HighscoreMeterHook`이 `SoundObject.Play()` 및 `SoundObject.PlayAndDestroy()` 메서드를 후킹하여 Clear 사운드를 교체합니다.
- 무한 모드를 위해 `Clear_FullCombo` 및 `Clear_FullCombo_JP`를 `KeyBlue_Tam` 오디오 클립으로 교체합니다.

## 미디어 재생 시스템

### 1. BGA (Background Animation)

게임은 `VideoPlayer` 컴포넌트를 사용하여 배경 영상을 재생합니다:

- **VideoPlayer.url**: 비디오 파일의 URL (로컬 파일의 경우 `file://` 프로토콜 사용)
- **VideoPlayer.source**: `VideoSource.Url`로 설정되어 URL에서 스트리밍합니다.
- **VideoPlayer.prepareOnAwake**: 비디오 준비 옵션
- **VideoPlayer.Prepare()**: 비디오를 준비하는 메서드 (비동기)

### 2. BGM (Background Music)

게임은 `AudioSource` 컴포넌트를 사용하여 배경 음악을 재생합니다:

- **AudioSource.clip**: 재생할 오디오 클립
- 게임은 `WWW` 클래스를 사용하여 오디오 파일을 로드할 수 있습니다:
  - MP3/WAV: 스트리밍 모드로 로드
  - OGG: 압축 모드로 로드
- `AudioClip.loadState`를 모니터링하여 로딩 진행 상황을 추적합니다.

## 결론

이 문서는 모드 코드가 후킹하는 메서드와 데이터 구조를 역으로 추론하여 게임의 원본 로직을 추정한 것입니다. 게임의 주요 동작 흐름은 다음과 같습니다:

1. **트랙 선택** → `SelectableTrackObject` 생성
2. **BMS 파일 로드** → `ManagerPlay.FetchBMSToModules()` 또는 `GetPatternFromDir()`
3. **BMS 파싱** → `SXGTReader.ReadBMSFile()` → `ParseString()` → `ParseBeatString()`
4. **SXGTData 생성** → `laneData`에 노트 데이터 저장
5. **노트 생성** → `NoteGenerator.Generate()`로 시각적 노트 오브젝트 생성
6. **게임 플레이** → `ManagerPlay`가 게임 상태 관리, `CheckGameFinished()`로 종료 체크
7. **게임 종료** → `FinishPlayScene()`으로 결과 화면 이동

게임은 BMS 파일 형식을 지원하며, 파싱된 노트 데이터를 게임 내부 형식으로 변환하여 리듬 게임을 구현합니다.
