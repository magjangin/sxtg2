## 전체 시스템 개요 (비유)

이 프로젝트는 **"외국어 레시피를 한국어로 번역해서 요리하는 시스템"**으로 비유할 수 있습니다.

### 비유 설명

1. **BMS 파일 = 외국어 레시피**
   - BMS 파일은 게임이 이해할 수 없는 형식의 차트 데이터입니다
   - 마치 영어로 된 레시피를 한국어로 번역해야 하는 것과 같습니다

2. **BmsParser = 번역가**
   - BMS 파일을 읽어서 게임이 이해할 수 있는 형식으로 변환합니다
   - 레시피의 각 재료(노트)를 한국어로 번역하고, 타이밍(조리 시간)을 계산합니다

3. **CustomChartInjector = 요리사**
   - 번역된 레시피를 받아서 실제 요리(게임 노트)를 만듭니다
   - 각 재료를 적절한 위치(레인)에 배치하고, 홀드 노트는 특별한 조리법으로 처리합니다

4. **Hook 시스템 = 주방 감시 시스템**
   - 게임이 원본 레시피를 사용하려고 할 때, 우리가 만든 커스텀 레시피로 교체합니다
   - 마치 주방에 감시 카메라를 설치해서 요리 과정을 가로채는 것과 같습니다

5. **BGA/BGM 교체 = 배경 음악과 영상 교체**
   - 요리하는 동안 들을 음악과 보여줄 영상을 교체합니다
   - 마치 레스토랑의 배경 음악과 TV 화면을 바꾸는 것과 같습니다

### 2. BmsParser.cs - 번역가

**비유: 전문 번역가**

```
번역가의 작업 과정:
1. 외국어 레시피(BMS 파일) 읽기
2. 각 재료(노트)를 한국어로 번역
3. 조리 시간(타이밍) 계산
4. 특수 재료(홀드 노트) 처리
5. 번역된 레시피(ParsedNote) 반환
```

**핵심 로직:**

#### 2.1 파일 파싱 (`ParseBmsFile`)
```csharp
// 비유: 레시피를 한 줄씩 읽으면서 재료 목록 작성
while ((line = streamReader.ReadLine()) != null)
{
    // 헤더 라인: 기본 정보 (#BPM = 기본 조리 속도)
    if (line.Contains(' '))
    {
        // BPM 정보 추출
    }
    // 데이터 라인: 실제 재료 (#00116:0203 = 1번 마디, 16번 채널, 02와 03 재료)
    else if (line.Contains(':'))
    {
        // 노트 데이터 파싱
    }
}
```

**비유 설명:**
- `#BPM 120` = "기본 조리 속도는 120 BPM입니다"
- `#00116:0203` = "1번 마디의 16번 채널에 02(홀드 시작)와 03(홀드 끝) 재료가 있습니다"

#### 2.2 시간 계산 (`CalculateTime`)
```csharp
// 비유: 조리 시간 계산
// tick = 마디 번호 + 마디 내 위치
// time = tick * 4 beats * (60 / BPM) 초
```

**비유 설명:**
- BMS의 tick은 "레시피의 몇 번째 단계"를 의미합니다
- 실제 시간(초)으로 변환하려면 BPM(조리 속도)을 고려해야 합니다
- 예: tick 1.5, BPM 120 → 1.5 * 4 * (60/120) = 3.0초

**코드 리뷰 포인트 (⚠️ 문서 작성 시점 기준)**:
- ✅ 복잡한 BPM 변화 처리 로직
- ⚠️ BPM 변화 채널(03, 04, 08) 미지원 (헤더의 #BPM만 사용)
- ⚠️ 시간 계산 로직이 복잡하고 주석이 부족함
- 📝 **현재 상태**: 실제 구현은 더 정교할 수 있음, BmsParser.cs 코드 확인 필요

#### 2.3 홀드 노트 길이 계산 (`CalculateHoldNoteLengths`)
```csharp
// 비유: 연속 조리 재료의 길이 계산
// 02(시작)와 03(끝)을 찾아서 길이 계산
// 예: 시작 시간 5초, 끝 시간 7초 → 길이 2초
```

**비유 설명:**
- 일반 홀드(02-03): "5초부터 7초까지 계속 조리하세요" → 길이 2초
- 이벤트 홀드(04-05): "특별한 재료를 3초부터 5초까지 조리하세요" → 길이 2초

**코드 리뷰 포인트 (⚠️ 문서 작성 시점 기준)**:
- ✅ 레인별로 그룹화하여 효율적으로 처리
- ⚠️ 매칭 실패 시 경고만 출력하고 계속 진행 (부분 실패 허용)

### 3. CustomChartInjector.cs - 요리사 (✅ 현재 대폭 개선됨)

**비유: 전문 요리사**

```
요리사의 작업 과정:
1. 번역된 레시피(ParsedNote) 받기
2. 각 재료를 적절한 위치(레인)에 배치

   - 홀드 노트(HOLD) = 연속 조리 (tickTime 배열 생성)

```

> ✅ **2026년 개선 사항**:
> - `NoteFactory` 클래스로 노트 생성 로직 분리 완료
> - `FieldSetter` 클래스로 필드 설정 모듈화
> - Enum 캐싱으로 성능 최적화
> - 실제 구현: [`CustomChartInjector.cs`](../sxtg2-mod/Processors/CustomChartInjector.cs), [`NoteFactory.cs`](../sxtg2-mod/Processors/CustomChartInjector.NoteFactory.cs), [`FieldSetter.cs`](../sxtg2-mod/Processors/CustomChartInjector.FieldSetter.cs)

**핵심 로직:**

#### 3.1 노트 주입 (`InjectBmsNotesToLaneData`)
```csharp
// 비유: 레인별로 재료를 정리해서 주방에 배치
// 1. 레인별로 그룹화 (0번 레인, 1번 레인, ...)
// 2. 각 레인에서 기존 재료 제거
// 3. 시간 순으로 정렬
// 4. 각 재료를 게임 형식으로 변환하여 추가
```

**비유 설명:**
- 레인 = 주방의 각 조리대
- 기존 노트 제거 = 조리대를 깨끗이 정리
- 시간 순 정렬 = 조리 순서대로 재료 배치

#### 3.2 게임 노트 생성 (`CreateGameNote` → NoteFactory)
```csharp
// 비유: 재료를 게임이 이해할 수 있는 형식으로 변환
// 1. 노트 타입 결정 (SHORT vs HOLD)
// 2. 노트 색상 결정 (BLUE vs RED vs OPEN)
// 3. 생성자 찾아서 호출
// 4. 홀드 노트는 tickTime 배열 생성 (기준 간격)
```

**비유 설명:**
- 생성자 찾기 = "어떤 조리법을 사용할까?" 결정
- tickTime 배열 = "홀드 노트를 누르고 있을 때 기준 간격마다 점수 체크"

**코드 리뷰 포인트 (⚠️ 문서 작성 시점 기준)**:
- ✅ 여러 생성자 패턴 지원 (2개 파라미터, 4개 파라미터, 기본 생성자)
- ⚠️ 리플렉션 사용이 많아서 성능 저하 가능성 → **✅ 현재: 캐싱으로 최적화됨**
- ⚠️ 생성자를 찾지 못하면 기본 생성자 + 필드 설정으로 대체 (fallback 로직)
- 📝 **현재 상태**: NoteFactory/FieldSetter로 분리되어 더 깔끔한 구조
