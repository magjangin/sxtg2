# 문서 구조 개선안

## 문제점 분석

현재 문서의 문제점:
1. **BMS 파싱에 치중**: 실제 게임 로직보다 BMS 파싱 설명이 과도함
2. **부정확한 타입 정보**: 실제 게임 타입(`RhythmGame.ShortNote`, `RhythmGame.HoldNote`) 정보 부족
3. **노트 생성 과정 불명확**: 생성자 호출과 필드 설정 과정이 불명확
4. **타입 추출 과정 누락**: laneData에서 실제 타입을 추출하는 과정이 문서화되지 않음

## 구체적인 개선 사항

### GAME_LOGIC.md에 추가할 내용

#### 1. 게임 타입 구조 (최우선)
```markdown
## 게임 타입 구조

### Note 타입 계층
- `RhythmGame.Note` (base 클래스)
  - `RhythmGame.ShortNote` (일반 노트)
  - `RhythmGame.HoldNote` (홀드 노트)

### laneData 구조
- 타입: `Dictionary<int, List<RhythmGame.Note>>`
- 각 레인(0-9)에 `List<Note>` 저장
- 파생 타입(ShortNote, HoldNote)을 base 타입(Note)으로 자동 캐스팅 가능
```

#### 2. 노트 생성 과정
```markdown
## 노트 생성 과정

### ShortNote 생성
1. 생성자: `ShortNote(float timing, int targetLane)`
2. 필드 설정: nType, nColor

### HoldNote 생성
1. 생성자 옵션:
   - `HoldNote(float timing, int targetLane)` + 필드 설정
   - `HoldNote(float timing, NoteType nType, NoteColor nColor, int targetLane, float duration)`
   - `HoldNote(float timing, NoteType nType, NoteColor nColor, int targetLane, float[] tickTime)`
2. 필드 설정:
   - duration
   - tickTime (float[])
   - tickLength (int)
   - tickJudge (bool[])
   - isFinished, isHeadJudged, elapsedTick
```

#### 3. 타입 추출 과정
```markdown
## 타입 추출 과정

### laneData에서 타입 추출
1. SXGTData 생성자 호출 시점에 laneData 접근
2. 각 레인의 noteList에서 실제 노트 타입 확인
3. `note.GetType()`으로 실제 타입 추출
4. 타입 이름으로 ShortNote/HoldNote 구분
5. 각 타입을 정적 변수에 저장
```

#### 4. 실행 시점
```markdown
## 실행 시점

### 원본 노트 제거 타이밍
- ❌ SXGTData 생성자 직후: 너무 이르다 (노트가 아직 감지되지 않음)
- ✅ ManagerPlayHook 메서드 호출 시점:
  - set_bms 호출 시
  - FetchBMSToModules 호출 시
  - GetPatternFromDir 호출 시
```
